# Безопасность

## Модель угроз

Панель предназначена для доверенной LAN. Она запускается от root (как и
большинство init-скриптов Entware), потому что должна управлять службой,
писать конфиг и вызывать `/opt/etc/init.d/forksmartdns`.

Защищаемые активы:

- конфигурация резолвера и списки;
- пароль администратора (хеш);
- резервные копии (содержат конфиг, списки, auth.conf);
- логи запросов (приватность: домены, которые посещают клиенты).

## Аутентификация

- Пароль: salted SHA-256, 150 итераций (`FSD_HASH_ITER`).
- Соль — 16 hex-символов из `/dev/urandom`; хеш — 64 hex.
- **Ограничение:** это не PBKDF2/Argon2/scrypt. При утечке `auth.conf`
  офлайн-подбор возможен быстрее, чем для современных KDF. Используйте длинный
  уникальный пароль; файл имеет права `0600`.
- Первая настройка — одноразовый токен из `setup-token` (24+ hex, `0600`),
  удаляется после задания пароля.
- 5 неудачных попыток → блокировка IP на 5 минут; каждая неудача дополнительно
  замедляется `sleep 1`.
- Смена пароля инвалидирует все сессии.

## Сессии

- Токен 32 hex в cookie `fsd_session`; `HttpOnly`, `SameSite=Strict`, TTL 8 ч.
- Хранится файлом `0600` в `/opt/var/run/forksmartdns/sessions/`.
- Привязка к IP: смена IP требует повторного входа.
- Logout удаляет только текущую сессию; смена пароля — все.

## CSRF и origin

- Все изменяющие запросы требуют заголовок `X-FSD-CSRF`, равный токену сессии.
- Для POST/PUT выполняется проверка `Origin`/`Host` (если `Origin` передан).
- Cookie `SameSite=Strict` — дополнительный барьер.

## Веб-сервер

- Отдельный экземпляр lighttpd на выбранном порту (по умолчанию `3636`).
- Docroot — только `www`; `server.follow-symlink = "disable"`.
- CSP: `default-src 'self'`, без внешних CDN/шрифтов/скриптов.
- `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: no-referrer`.
- CGI-бэкенд — единственная точка выполнения кода; статика не содержит секретов.

## Файлы и пути

- Конфиг, auth, instance.env, архивы — `0600`; каталоги run/backups — `0700`.
- API для списков принимает только плоские имена `[A-Za-z0-9._-]{1,128}`,
  отклоняет `/`, `..`, ведущую точку; файлы лежат только в `lists/`.
- Скачивание backup — только из `$VAR/backups` по имени, прошедшему проверку.
- Симлинки в docroot не поддерживаются.
- API не использует `eval` для пользовательских данных; `header_get` работает
  только с фиксированными именами заголовков.

## Что НЕ сделано

- **Нет TLS для панели.** Пароль и cookie идут по HTTP в LAN. Для удалённого
  доступа используйте SSH-туннель (`ssh -L 3636:127.0.0.1:3636 root@router`) или
  VPN, а лучше привяжите панель к LAN-адресу (`--ui-bind 192.168.1.1`).
- Нет 2FA.
- Нет отдельного непривилегированного пользователя для CGI: управление службой
  требует root.
- Нет защиты от атак, если порт опубликован в интернет. Не публикуйте.
- Нет подписи архивов backup; целостность обеспечивается правами доступа.
- `bind-cert-*` для DoH/DoT-услышителей настраивается в сыром конфиге; ядро
  умеет генерировать самоподписанный сертификат, но панель не управляет
  выпуском доверенных сертификатов.

## Рекомендации

1. Привяжите панель к LAN-IP роутера: `--ui-bind 192.168.1.1`.
2. Используйте длинный пароль (≥ 16 символов) и меняйте его при подозрении.
3. Не открывайте порт панели в интернет; для внешнего доступа — SSH/VPN.
4. Ограничьте доступ к `/opt/etc/forksmartdns/auth.conf` и backups.
5. Проверяйте `forksmartdnsctl diagnose` после обновлений.
6. Делайте backup перед ручным редактированием конфигурации.
7. Помните, что логи содержат домены клиентов; не публикуйте их.
